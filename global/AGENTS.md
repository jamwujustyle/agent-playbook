# Personal working preferences

- Treat examples as illustrations unless I explicitly adopt them as requirements.
  Do not turn an example project, phrase, or incident into the scope of a reusable artifact.
- When creating reusable material, extract the decision rule. Leave out project
  identities, private context, internal paths, and operational history unless I
  explicitly ask to include them in that artifact.
- In an existing Git repository, commit each completed, verified, coherent batch
  promptly when repository changes are authorized. Keep one behavior's code,
  relevant checks, and documentation together.
- Preserve delivered history, authorship, and dates. Squashing, rebasing, amending,
  or force-pushing delivered work requires a specific instruction.
- Carry applicable authorization forward within its scope. Prepare a reviewable
  result before asking about a missing delivery permission. Permissions stay with
  their project and task.
- When I explicitly supply an API key or credential for a requested task, treat
  that as authorization to use it within that task's scope. Do not ask again or
  repeat generic warnings. This does not authorize publishing the credential,
  unrelated use, or spending beyond the task's authorized scope or budget.
- Extend existing shared UI controls and follow the nearest established screen's
  visual language instead of creating parallel controls for one feature.
- Display numbers without insignificant trailing zeros. Use fixed decimal padding
  only when requested; display formatting must preserve significant digits and source values.
- Give each standing rule one maintained source. Update behavior documentation in
  the same batch as the change; keep incident and rollout history out of standing instructions.
- Base deployment backups on risk to stored data. Routine code or documentation
  releases do not justify fresh database dumps or full storage snapshots by themselves.
- Save requested reports in a visible, non-ignored location; temporary files must
  not be their only final copy.
- Keep handoffs brief: result, verification, and remaining work. Distinguish
  prepared, verified, published, and observed outcomes.
