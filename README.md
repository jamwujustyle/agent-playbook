# Личный набор правил для разработки

Подготовлен 16 октября 2026 (Asia/Almaty) по документации Nara, Nara Lite и Partner Desk.
Исходники набора: [jamwujustyle/agent-playbook](https://github.com/jamwujustyle/agent-playbook).
Публикация репозитория не устанавливает правила в Codex. Подключение выполняется отдельно.

## Рекомендуемая схема

| Слой | Содержимое | Подключение |
| --- | --- | --- |
| [Общий AGENTS.md](global/AGENTS.md) | Постоянные предпочтения разработки | `~/.codex/AGENTS.md` или `$CODEX_HOME/AGENTS.md` |
| [Локальный шаблон](project/AGENTS.template.md) | Стек, команды, инварианты, разрешения конкретного проекта | Адаптировать в `<project>/AGENTS.md` |
| [prompt-engineering](skills/prompt-engineering/SKILL.md) | Проектирование поведения LLM-продукта | Личный или проектный каталог skills |
| [evidence-audit](skills/evidence-audit/SKILL.md) | Аудит качества, эффект релиза, сравнение стоимости | Личный или проектный каталог skills |
| [Политика выпуска](references/release-policy.md) | PR, deploy, backup по риску | Принять и адаптировать только при наличии выпуска |
| [Деньги и события](references/money-events.md) | Точность, права, доказательства, идемпотентность | Подключать только к соответствующей области |

Набор переносит личные рабочие правила между проектами независимо от их назначения.
Два навыка выделяют повторяемые процедуры из исходной документации; их полные
инструкции нужны только для подходящей задачи.
Стек Go/Next/Docker, домены, ключи, аккаунты, платёжные истории, gambling-политика и
production-разрешения остаются в исходных проектах. Запрет комментариев Go-функций
сохранён как кандидат для локального Go-профиля в SOURCES, а не правило для любого языка.

Глобальный AGENTS читается вместе с локальными инструкциями. Более близкие к рабочему
каталогу инструкции уточняют предыдущие; `.override` может заменить обычный файл
на том же уровне. Навыки загружаются по задаче, поэтому обязательную общую дисциплину
не стоит прятать исключительно в skill. См. [официальное устройство AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

В Nara Lite исходный AGENTS занимает 47 196 байт; документированный стандартный
лимит цепочки инструкций — 32 КиБ. Это риск автоматического усечения при обычном
обнаружении, а не утверждение, что в этом чате часть явно переданных правил потерялась.
Увеличение лимита не устраняет дублирование и устаревшую историю.

## Установить один раз

Нужны Git и Python 3. Установщик рассчитан на Linux/macOS с поддержкой символьных ссылок;
на Windows работа не проверялась. Клонируй репозиторий в постоянную папку:

```bash
git clone https://github.com/jamwujustyle/agent-playbook.git
cd agent-playbook
```

Посмотри план установки:

```bash
python3 install.py
```

Команда показывает план, ничего не меняет. Для установки после просмотра:

```bash
python3 install.py --apply
```

Установщик копирует базовый AGENTS в Codex home и делает ссылки на две папки skills
в `~/.agents/skills` — актуальном пользовательском каталоге по
[официальной документации навыков](https://learn.chatgpt.com/docs/build-skills).
Непустой отличающийся AGENTS или чужие папки/ссылки он не заменяет: завершает работу
до изменений и сообщает конфликт. Их нужно осмысленно объединить, не затереть.
Нестандартные пути можно передать через `--codex-home` и `--skills-dir`.

Установщик проверяет текущее содержимое файлов при каждом запуске.
Ссылки зависят от расположения этой папки: после установки не перемещай её без обновления ссылок.
Обновление скопированного AGENTS требует повторного сравнения; навыки читают файлы по ссылкам.
Установка не создаёт автозапусков, сетевых запросов или прав на production.

После подключения начни новый чат в проекте и попроси назвать активные источники
инструкций. Проверь, что навыки доступны; если обновление не появилось, перезапусти Codex.
Каталоги, уже показанные приложением в другом расположении, не стоит дублировать:
одноимённые skills не сливаются автоматически. Другие каталоги навыков
установщик не изменяет.

## Подключить только к одному проекту

Скопируй нужные навыки в `<project>/.agents/skills/` и объединённые общие + локальные
правила в `<project>/AGENTS.md`. Не заменяй существующие правила целиком.
Файлы release-policy/money-events копируй только если они нужны, затем добавь
реальные ссылки в карту документации. Шаблон сам по себе не является готовой политикой.

Для проекта на другом компьютере или в облаке глобальные файлы этого компьютера
не появятся сами. Нужна установка на той среде либо включение нужных файлов в проект.
В другом coding-инструменте проверь поддерживаемые им пути инструкций и skills.

Пример явного использования навыков:

> Используй prompt-engineering: исправь повторяющиеся вопросы, сохранив цель и тон.

> Используй evidence-audit: сравни результат релиза с предыдущим окном, сохрани IDs проблем.

В интерфейсах с выбором навыков используй соответствующий selector; в Codex CLI/IDE
поддерживается упоминание `$prompt-engineering` / `$evidence-audit`.

## Роль GitHub и обновления

Этот репозиторий хранит версии набора и позволяет перенести его на другой компьютер.
В публичный пакет входят переносимые правила и краткая карта их происхождения;
исходные документы продуктов, локальные пути, клиентские данные и credentials не включены.

GitHub — место хранения и обновления. Одна ссылка в чате не устанавливает постоянные
инструкции: один раз клонируй набор и подключи его, затем обновляй осмысленно через diff.
Изменения не синхронизируются автоматически. Обновляй локальный checkout после
просмотра diff; установленные через ссылки навыки затем читают новую версию.
Для изменения скопированного AGENTS сравни и объедини его с обновлённой базой:
установщик намеренно не перезаписывает отличающийся непустой файл.

Для распространения другим людям с установкой через каталог можно позже упаковать
навыки в plugin; для вашего личного набора сейчас достаточно папки и Git.
Официальная документация [разделяет постоянные инструкции, навыки и плагины](https://learn.chatgpt.com/docs/customization/overview).

## Как поддерживать

При повторяющейся ошибке уточняй один ответственный источник. Универсальный принцип
идёт в базу; процедура — в навык; специфика продукта — в его AGENTS; история — в отчёт.
Не добавляй новое вечное правило после каждого единичного случая и не копируй целиком
разросшийся проектный AGENTS в новый проект. Проверяй и противоположную ошибку.

[SOURCES.md](SOURCES.md) содержит происхождение правил, решения по противоречиям
и ограничения чтения. [VALIDATION.md](VALIDATION.md) — фактически выполненные проверки.
