# Необязательная политика выпуска

Это переносимый проект политики на основе практики Nara Lite. Включение этого
файла в репозиторий само по себе не выдаёт права на push, merge или production.
Сначала запиши разрешённые операции и окружения в локальном AGENTS.md.
Более строгая действующая политика конкретного проекта сохраняется до её изменения.

- Выпускай законченную проверенную партию целиком: реализация, необходимые тесты,
  документация. Для значимого отдельного изменения предпочитай отдельный PR;
  не дроби одну задачу и не создавай косметическую активность ради счётчиков.
- При разрешённом merge сохраняй исходные коммиты обычным merge/fast-forward.
  Соблюдай branch protections и проверки. Проверь достижимость выполненных
  коммитов из удалённой основной ветки; название ветки и аккаунт не угадывай.
- Сначала сверяй кандидат с реально работающей версией, чтобы не откатить более
  новый релиз. Деплой только зафиксированного кода по локальному runbook.
  Не запускай seeds, меняющие пользовательские настройки, без соответствующего поручения.
- После выпуска проверь здоровье и релевантный пользовательский сценарий.
  Healthy-процесс не доказывает правильность поведения. Запиши версию и cutover.
- Если изменились только документы, обычно достаточно обновления checkout и
  проверки состояния без rebuild, restart, миграций и seeds, если так устроен deploy.
- Резервное копирование оценивай по риску данным. Обычный код/UI/docs и чисто
  добавочные миграции сами по себе не требуют полного дампа и архива медиа.
  При удалении, несовместимой миграции, массовой перезаписи, перемещении данных,
  изменении шифрования или расчётной истории нужна подходящая проверенная копия.
  Укажи конкретный риск и затронутый объём; не дублируй пригодную копию при retry.
- Перед изменением production env/сертификата сохрани небольшую копию затронутого
  файла с прежними правами. Не копируй неизменённый env на каждом выпуске.
- Проверяй ресурсный запас перед сборкой. Пороги, пути и разрешённая очистка
  принадлежат локальному runbook. Не удаляй существующие backup, чужие процессы
  и production-образы, не добавляй регулярную очистку без отдельного разрешения.
- При блокировке укажи конкретно непрошедший шаг. Push ветки, открытый PR и локальная
  проверка не заменяют merge/deploy, когда они входят в согласованную поставку.
